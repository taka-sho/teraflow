## 9. Issueテンプレート

### 9.1 全ステージ共通

**要求起票テンプレート（非エンジニア向け）**: 技術用語を一切使わない。やりたいこと / 背景 / 利用者 / 理想の動き / 優先度 / 参考資料。自動ラベル: `phase:要求整理`, `assignee:unset`。

**手戻りテンプレート**: 発覚したフェーズ / 原因のあるフェーズ / 関連Issue / 不備の内容 / あるべき姿。自動ラベル: `rework`。全ステージ・全フェーズで受付可能。

### 9.2 運用ステージ用

**障害報告テンプレート**: 発生日時 / 影響範囲 / 事象 / 重大度（critical/major/minor） / 再現手順 / 暫定対応。自動ラベル: `stage:運用`, `incident`。

**問い合わせテンプレート**: 問い合わせ内容 / 問い合わせ元 / 期限。自動ラベル: `stage:運用`, `inquiry`。

### 9.3 継続的改善ステージ用

**改善要求テンプレート**: 要求起票テンプレートと同じ設問だが、ラベルに `stage:継続的改善` を付与。対象サイクル（Milestone）を選択する項目を追加。

### 9.4 保守ステージ用

**保守作業テンプレート**: 作業種別（セキュリティパッチ / ライブラリ更新 / リファクタリング / EOL対応） / 対象 / 緊急度 / 影響範囲。自動ラベル: `stage:保守`, `maintenance`。

### 9.5 その他

要件定義・基本設計・詳細設計・実装・テストの各テンプレートは前版と同一。各テンプレートに `stage:` ラベルと `phase:` ラベルの両方を設定する。

## 10. Discussions: 非エンジニアの入口

Discussions は3層責務モデル（セクション1）における「非構造的な入口」として機能する。要求フェーズ専用。

**Discussion の役割**:
- 非エンジニアが気軽に要望・相談を投稿する場
- AI エージェントとの対話で要求を整理する場
- 「要求確定」で Issue 化 + 成果物ファイル生成をトリガーする場

**Discussion → Issue → File の流れ**:

```
非エンジニアが Discussion に投稿
  → AI対話で要求を整理
  → 「要求確定」コメント
  → Actions が自動で:
     ├── REQ-XXXX.md を生成（docs/01_requirements/）
     ├── PR を作成
     ├── Issue を自動作成（作業追跡用、PR マージ後に自動クローズ）
     └── Discussion にステータスコメントを投稿
```

要件定義以降のフェーズでは Discussion は使わず、Issue 上で直接 AI 対話を行う。非エンジニアが関わるのは主に要求フェーズまでであり、それ以降はエンジニアが Issue を起点に作業する。

継続的改善ステージでも同じ Discussion × AI対話のフローを使用する。
