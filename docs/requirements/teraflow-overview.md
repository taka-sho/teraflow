# teraflow 要件概要

## 1. 目的

teraflow は、要件定義から設計・実装・検証・改善までのソフトウェア開発ライフサイクルを、
CLI 操作とドキュメント駆動で一貫管理するための開発支援基盤である。

本要件は、個人開発から小規模チーム開発までを対象に、
「作業手順の明確化」「変更の追跡可能性」「品質ゲートの継続運用」を実現することを目的とする。

## 2. 対象ユーザー

- 個人開発者: 開発手順を標準化し、再現可能な開発フローを維持したい利用者
- 小規模開発チーム: 役割分担とレビュー運用を明確化し、進捗を可視化したいチーム
- 技術リード/マネージャ: フェーズ遷移、品質指標、リスクを一元把握したい責任者

## 3. 主要機能

- プロジェクト初期化と状態管理
  - `teraflow init` / `status` / `stage` / `phase` によるライフサイクル管理
- 要件・設計・実装のトレーサビリティ
  - CoDD(frontmatter) による依存関係管理と影響範囲分析
- 品質ゲートの運用
  - テスト、lint、ビルド、セキュリティチェックの実行と結果可視化
- 運用支援
  - リワーク、インシデント、変更履歴の記録と追跡
- GitHub 連携（段階導入）
  - Discussion/Issue/PR を利用した共同作業と自動化ワークフロー

## 4. スコープ

### 4.1 スコープ内

- CLI ベースの開発ライフサイクル管理
- docs/ を中核としたドキュメント駆動運用
- ローカル環境と CI 上での品質検証
- フェーズ制御、ゲート判定、リワーク管理

### 4.2 スコープ外

- 大規模組織向けの統合認証基盤（SSO/IDP）
- フルマネージド SaaS としての提供
- 他社 ALM ツールへの全面的な双方向同期

## 5. 補足

本概要は上位要件として機能し、個別要件（機能要件、非機能要件、運用要件）は
`req:*` ノード群で詳細化する。
